# ECI-CAS end-to-end code review, v2

**Review date:** 2026-09-17  
**Status:** Working review and remediation plan  
**Scope:** `EciCas.Core`, `EciCas.Bus`, `EciCas.Agents`, `EciCas.Substrates`, `EciCas.Host`, `EciCas.Shell`, `EciCas.ArchiveTool`, tests, and the authored React/TypeScript client.

## Review standard and limitations

`AGENTS.md` is the authoritative standard for this review. The key invariants are asynchronous message passing, non-blocking publication, agent independence from delivery timing and ordering, archive integrity, correct cancellation and failure handling, reliable live telemetry, and minimal changes.

Generated and vendored content such as `bin`, `obj`, `.next`, `out`, and `node_modules` is not treated as authored source. Generated frontend bundles are used only to identify source modules when the original TypeScript is unavailable.

The findings below are based on source inspection. They do not claim that builds, tests, linters, or runtime scenarios were executed unless explicitly stated.

## v2 triage changes

This version incorporates the subsequent challenge review rather than treating every original concern as an equally confirmed defect.

- **Confirmed and actionable High findings:** H3, H5, H6, H7, H8, and H9.
- **Open validation finding:** OPEN-H1. The concluded-turn cache is relevant mitigation, so the Governance concern must be proven or disproved through a complete state-path inspection and deterministic ordering tests.
- **Operational hardening risks:** M16 and M17, formerly H2 and H4. Unbounded queues and permanent subscriptions fit the current long-lived hosted-service design, but retain measurable resilience and restart/test-isolation risks.
- **No finding is resolved by a source comment alone.** Close a finding with a demonstrated invariant, a focused regression test, or direct evidence that the path cannot occur.
- The short review/checklist is a validation plan, not proof that every listed scenario is currently broken.

## Repository assessment

The solution is divided into contracts, bus infrastructure, cognitive and persistence agents, model substrates, HTTP/SSE composition, a desktop shell, an archive tool, tests, and a React/TypeScript client. The runtime flow is broadly:

```text
React or shell input
  -> Host endpoint or callable Perception boundary
  -> Core envelope and message bus
  -> independent advisory agents
  -> Governance bundle
  -> Intent proposal
  -> Security verdict
  -> Governance action and conclusion
  -> Scribe, Reflection, telemetry and turn projection
  -> SSE and React state
```

This separation is directionally sound. The most important confirmed problems are in persistence identity/finalization, configuration writes, cancellation ownership, work recovery, and obsolete Archivist-era production code. The most important unresolved question is whether Governance terminal state is protected on every state-creating and publishing path.

# Findings

## Critical

No Critical defect is confirmed from the inspected source. This does not establish that the repository contains none. The complete persistence implementations, security rule implementation, all substrate providers, all Host endpoints, Shell resource ownership, and all authored React modules still require direct source review before making a repository-wide assurance.

## High

### H3. Knob persistence uses synchronous, non-atomic, unlocked file writes

**Status:** Confirmed and actionable.

**Evidence**

`EciCas.Host/Endpoints/KnobsEndpoints.cs` handles `/api/knobs/save` with direct read-modify-write operations using synchronous file APIs. It writes runtime-output and source-tree configuration targets sequentially. The inspected path does not show serialization, temporary-file replacement, transaction-like rollback, or a distinct persisted-state model.

**Impact**

- Concurrent saves can overwrite one another.
- A process interruption can leave invalid or truncated JSON.
- One target can be updated while another fails, creating configuration drift.
- Disk I/O blocks the request path.
- Mutating bound option defaults after persistence conflates startup configuration with live/persisted state.

**Recommended fix**

- Move file persistence behind a small dedicated service.
- Serialize save operations with `SemaphoreSlim`.
- Use asynchronous I/O.
- Write to temporary files in the target directory, flush, validate, and atomically replace where supported.
- Do not update the persisted in-memory snapshot until all required targets commit.
- Keep live runtime knobs separate from the persisted snapshot.

**Required tests:** TEST-H3.

### H5. Scribe can assign the same turn number to concurrent perceptions

**Status:** Confirmed and actionable.

**Evidence**

`EciCas.Agents/Utterances/ScribeAgent.cs` derives a new turn number from `TurnsRecorded + 1` when accepting Perception. The durable count advances later during conclusion. Two perceptions accepted before either conclusion can therefore observe the same count and receive the same turn identity.

**Impact**

- Two utterances and replies can share a turn number.
- Reply pairing and previous-reply lookup can become ambiguous.
- Extraction context can cross-contaminate turns.
- Archive reconstruction becomes unreliable.

**Recommended fix**

Allocate the turn atomically when Perception is accepted. Prefer store-owned reservation tied to correlation ID. If allocation remains in-process, initialize an atomic allocator from durable state and define restart recovery for reserved but unfinalized turns. Persisted state should distinguish highest allocated turn, finalized-turn count, and correlation-to-turn mapping.

Do not fix this with a lock around a read of `TurnsRecorded + 1` unless allocation is advanced durably under the same operation.

**Required tests:** TEST-H5.

### H6. Scribe finalization is not idempotent for unknown or duplicate conclusions

**Status:** Confirmed and actionable.

**Evidence**

The inspected Scribe conclusion path conditionally writes a reply only when its open-turn lookup succeeds, but advances the global turn record outside that successful-open condition. A duplicate, replayed, or unknown Conclusion can therefore alter the count without a matching open input.

**Impact**

- Duplicate conclusions can shift every later turn number.
- Turn-number gaps can be unrelated to real turns.
- Combined with H5, the archive can both duplicate and skip identities.
- Replayed bus traffic is not idempotent.

**Recommended fix**

Return without finalization when the correlation ID is not open. Make store finalization idempotent by durable turn identity. A repeated finalization should be a no-op or a clearly classified conflict, not another count update.

**Required tests:** TEST-H6.

### H7. Reflection can lose an in-memory batch during shutdown or partial flush

**Status:** Confirmed and actionable.

**Evidence**

`EciCas.Agents/Reflection/ReflectionAgent.cs` copies pending material into a batch and clears the pending list before awaiting substrate and persistence work. Shutdown cancellation is excluded from the ordinary recovery path. Cancellation after the clear but before complete persistence can therefore leave no in-memory batch to retry.

**Impact**

- Pending reflection material can disappear during normal shutdown.
- A model response can complete while passage writes remain incomplete.
- Partial commits can duplicate on retry unless writes are idempotent.

**Recommended fix**

Either persist pending input before removal or restore/reconstruct the batch after any incomplete flush, including shutdown cancellation. If conclusions are sufficient to reconstruct pending reflection work, prefer restart reconstruction over another durable queue. Passage writes must be idempotent or carry stable identifiers.

**Required tests:** TEST-H7.

### H8. Sight replaces pending work without owning its cancellation or telemetry attribution

**Status:** Confirmed and actionable.

**Evidence**

`EciCas.Agents/Sight/SightAgent.cs` stores one pending task and replaces the task reference when a new glimpse begins. Replacing a reference does not cancel prior work. Pre-turn traces are held separately, so overlapping captures can detach model work and telemetry from the intended capture.

**Impact**

- Abandoned vision calls continue consuming resources.
- Trace, cost, latency, or model metadata can be assigned to the wrong turn.
- Repeated microphone activation can accumulate active work.
- Old screenshot work can outlive and interfere with a newer capture.

**Recommended fix**

Represent pending Sight work as one owned object containing a capture sequence, task, cancellation source, and capture-specific telemetry. Atomically replace it, cancel and dispose the previous capture, and publish only the result and traces belonging to the capture collected for the turn.

**Required tests:** TEST-H8.

### H9. The replaced Archivist remains executable and tested production code

**Status:** Confirmed dead runtime implementation with live compile-time coupling.

**Evidence**

Host registration uses Scribe as the active write-side path and does not register Archivist. `ArchivistAgent.cs` nevertheless remains a complete production agent and has tests for the obsolete extraction flow. Current implementations and tests still reference Archivist-owned metadata constants.

**Impact**

- The repository appears to support two write architectures.
- Obsolete tests consume maintenance effort without protecting the current path.
- Accidental re-registration could duplicate extraction.
- Current code cannot delete Archivist because current contracts are declared on it.

**Recommended fix**

Move current archive-control keys to a narrowly scoped Core contract or the active Scribe owner. Update current agents, projection, and tests. Delete the obsolete implementation and rewrite only tests that protect current extraction, weaving, minting, and Scribe behavior. Treat this as deletion, not as an abstraction project.

**Required tests:** TEST-H9.

## Open validation finding

### OPEN-H1. Validate whether late Perception or Advisory can recreate a concluded Governance turn

**Status:** Unresolved. Do not describe as a confirmed defect until tested or proven from every terminal-state path.

**Evidence under review**

The original review identified `GetOrAdd` paths in Governance for Perception, Advisory, and early Verdict handling, combined with state removal after conclusion. The challenge review correctly points out that Governance contains a concluded-turn cache intended to prevent duplicate terminal work.

The existence of that cache is relevant mitigation, but not complete proof by itself. The decisive question is whether every path that creates state or publishes a Bundle checks terminal status at the correct moment, including paths racing with final Verdict and paths occurring after retention eviction.

**Potential impact if confirmed**

- Duplicate Intent and Security calls.
- Incorrect telemetry or cost attribution.
- Duplicate downstream cycles for one correlation.
- Ordering-dependent behavior contrary to the central architecture invariant.

**Disposition**

Run TEST-OPEN-H1 before changing production code. If all cases pass and source inspection shows terminal checks around every state-creating and publishing boundary, close the finding and retain the test. If a duplicate Bundle or downstream cycle occurs, restore High severity and patch the smallest failing boundary.

## Medium

### M1. Current projection and agent contracts still depend on Archivist-era ownership

**Status:** Confirmed obsolete coupling. Address with H9.

Move active write/control keys away from the obsolete class and update Scribe, Identity, Impulse, Reflection, TurnProjection, and their tests.

### M2. Turn projection can regress `StartedAt` for late duplicate Perception

`TurnProjection.ApplyPerception` should retain the earliest observed timestamp rather than unconditionally replacing the start time. Add an out-of-order duplicate-Perception test.

### M3. Activity tracking observes zero but does not establish stable quiescence

`WhenIdleAsync` can observe zero immediately before new follow-on publication. This means “zero observed” rather than a synchronized cascade boundary. Add a generation/version check or an awaitable transition that confirms zero remains stable across a scheduling boundary.

### M4. Expected shutdown cancellation may escape the agent consumer loop

The consumer boundary should explicitly absorb `OperationCanceledException` only when the host stopping token is canceled. A substrate timeout or unrelated cancellation must still be handled as a real operation failure.

### M5. Frontend profile loading lacks cancellation and error fidelity

The identified `app/page.tsx` flow starts asynchronous profile work from an effect and reduces failures to generic messages. Verify the authored source. Pass `AbortSignal` through client functions, cancel on cleanup, prevent stale request commits, and retain structured diagnostic categories.

### M6. Generated frontend artifacts obstruct source and dead-code analysis

Exclude `.next`, `node_modules`, `out`, `bin`, `obj`, coverage, test results, and Git internals from the indexing/synchronization boundary. This is an indexing hygiene issue, not proof that those paths are committed.

### M7. Toolkit runs have no timeout or terminal cleanup

Track start time and expire unfinished runs through an explicit failed terminal state. Do not silently remove them.

### M8. Multiple Toolkit results can be arbitrarily ordered and overwritten

Aggregate completed Toolkit results into one advisory per Perception, ordered by stable start or completion metadata, or model them as independently consumed typed events. Avoid publishing multiple same-agent advisories into a Governance slot keyed only by publisher.

### M9. Identity invalidation depends on a broad legacy archive-written event

Use an explicit persona-change signal or a cheaply observable store version. Cache correctness should not depend on every writer knowing an Archivist-era broadcast convention.

### M10. Hindsight activation recognizes only English second-person forms

Use a deterministic address-detection service driven by the supported language or carry an explicit addressed-to-persona signal from the input boundary. Do not grow an ad hoc multilingual pronoun regex inside the agent.

### M11. Consult reports retrieval failure as a successful empty lookup

A successful empty lookup and an unavailable retrieval path must remain distinct. On failure, omit the recalled-facts value and attach an explicit degraded/unavailable marker. Add an Intent-level and UI-level contract test.

### M12. Previous-reply lookup may read the entire reply collection

This remains a performance risk until the concrete store is inspected. If `RepliesAsync` returns full history, replace it with a query for the immediately previous reply. If the implementation is already bounded, close the finding.

### M13. Reflection batch size has competing configuration owners

Choose one owner for the live batch threshold, remove or obsolete the other, and add a configuration-binding test.

### M14. Sight conversation state is singleton and not explicitly scoped

If multiple profiles, windows, or clients can submit concurrently, state can cross conversations. Either enforce one active conversation at the API boundary or key continuing state by an explicit conversation/profile identifier.

### M15. Intent combines untrusted evidence and instruction prose in one free-form prompt

Treat screen text, recalled facts, notes, and user content as evidence rather than instructions. Prefer structured role/content messages where supported. Otherwise encode and delimit each source, cap each independently, preserve provenance, and state the data/instruction distinction in static instruction content. Do not build a custom prompt-sanitization regex.

### M16. Unbounded per-subscriber queues create an operational memory-growth risk

**Formerly H2. Reclassified as resilience hardening.**

The unbounded per-subscriber design is consistent with non-blocking publication and long-lived agents. It is not automatically a defect. A stalled handler can still accumulate retained envelopes, so queue depth and in-flight behavior should be measurable. Introduce bounds or overflow behavior only with an explicit per-subscriber policy and a demonstrated requirement. Never silently drop persistence or cognitive events.

### M17. Permanent subscriptions create restart and test-isolation risk

**Formerly H4. Reclassified as lifecycle hardening.**

Permanent subscriptions match the current process-lifetime hosted-service model. Add deregistration only if restart, dynamic lifetimes, or shared-bus test reuse are supported. If those scenarios are unsupported, document the boundary rather than expanding the bus abstraction preemptively.

## Low

### L1. Governance terminal retention is count-based rather than time-based

A fixed number of concluded IDs is not a duration. Evaluate only after TEST-OPEN-H1 establishes whether late-event retention affects correctness.

### L2. Agent identities are repeated as string contracts

Move public roster/advisory identity to a shared typed kind or Core constants where rename-sensitive cross-project matching exists.

### L3. Historical comments obscure current invariants

Keep comments that explain current behavior. Move incident narratives and removed-agent history to the designated appendix or version history.

### L4. Empty or whitespace-only Perception can enter the agent graph

Reject empty input at the Perception boundary unless an empty nudge is intentional. If intentional, represent it with an explicit event kind.

### L5. Security implementation requires direct rule-set inspection

The agent's synchronous deterministic shape is appropriate if evaluation is small and rules are compiled once. Inspect `SecurityRuleSet` before making a performance or cancellation claim.

### L6. Security tests need adversarial-normalization review

Whether Unicode normalization, zero-width characters, homoglyphs, line boundaries, pathological patterns, or oversized input tests are required depends on the actual rule set.

### L7. Some prose-like Intent framing remains embedded in C#

Apply the `AGENTS.md` test: if wording should be editable without rebuilding, move it to instruction content. Keep genuinely runtime-generated framing in code.

### L8. Current comments still describe removed agents

Remove Librarian/Archivist-era descriptions while completing H9. Do not preserve obsolete architecture in current XML documentation.

# Positive findings

- Publication is designed to be synchronous and non-awaiting.
- Agents claim their subscriptions before worker loops begin.
- Ordinary handler failures are isolated from other agents.
- Governance snapshots advisory state rather than enumerating a mutating collection.
- Turn projection generally maps named event fields rather than relying on display arrival order.
- Important persona and degraded-response prose is held in instruction files.
- The frontend validates a remembered profile ID against profiles returned by the host.
- The avatar implementation includes reduced-motion behavior.
- Envelope creation and derivation maintain a clear correlation lineage, though metadata forwarding remains an explicit caller responsibility.

The asynchronous cache locking appears well structured. Replace broad legacy invalidation with a specific current contract.

## `SightAgent.cs`

Separation of OCR, model description, and reading mode is useful. H8 is the primary confirmed issue; M14 depends on supported conversation concurrency.

## `ScribeAgent.cs`

The ground-truth-first direction is sound. H5 and H6 are the most serious confirmed persistence findings and should be fixed together.

## `ReflectionAgent.cs`

Locking around pending collection mutation is useful, and expensive work occurs outside the lock. H7, M13, and legacy contracts remain.

## `ToolkitManagerAgent.cs`

Carrying completed asynchronous results into a later live turn is a defensible design. Add terminal expiry and aggregate same-turn results.

## `ArchivistAgent.cs`

Dead runtime implementation. Remove after relocating current shared contracts.

## `SubstrateTrace.cs`

Unavailable token/cost data is represented separately from zero and failed-call latency is retained. Update obsolete examples during H9 cleanup.

# Required regression tests and validation plan

## Test rules

- Test observable behavior and durable state, not private fields.
- Use deterministic gates and fakes instead of sleep-based races.
- Do not make correctness assertions depend on subscriber execution order.
- Concurrency tests must fail against the defective implementation for the intended reason.
- Persistence tests must use isolated temporary storage and verify restart behavior.
- Never report a test as passing unless it was executed successfully.

## TEST-H3: Knob save is serialized, atomic, and failure-safe

**Arrange:** Create isolated source and runtime JSON files. Start two save operations with different values. Gate both after read and before commit through an injectable persistence boundary.

**Assert:**

- Both targets remain valid JSON.
- Both contain one complete committed value set, never a mixture.
- In-memory persisted state changes only after all required targets commit.
- Temporary files are cleaned after success.
- Failure of the second target does not silently leave target drift.
- Cancellation before replacement leaves the original file intact.

## TEST-H5: Concurrent perceptions receive unique durable turn identities

Accept two correlations before either concludes, then conclude in reverse order.

**Assert:**

- Distinct turn identities.
- Correct reply pairing.
- Exactly one durable allocation per accepted turn.
- No identity reuse after restart.
- Append/reservation failure follows a documented atomic recovery policy.

## TEST-H6: Conclusion finalization is idempotent

Deliver one valid Conclusion twice and one unknown Conclusion.

**Assert:**

- One reply and one finalized-turn record for the valid correlation.
- No count or archive change for duplicate or unknown conclusions.
- Replay after process recreation leaves durable state unchanged.

## TEST-H7: Reflection survives cancellation and partial commit

Block independently before substrate completion, before first write, and after a partial write. Cancel the host token.

**Assert:**

- Work is restored or deterministically reconstructable.
- Retry creates each logical passage at most once.
- Ordinary failures and shutdown cancellation follow explicit recovery behavior.

## TEST-H8: New Sight capture cancels old work and owns its telemetry

Run capture A and hold it. Start B, then complete or fail A after replacement.

**Assert:**

- A is canceled and cannot publish for B.
- Only B's result and traces attach to B's turn.
- A's exception is observed.
- Repeated replacement does not accumulate active work.

## TEST-H9: Runtime and current contracts no longer depend on Archivist

**Assert:**

- No production registration resolves Archivist.
- No active production class imports the obsolete namespace.
- Current shared keys have a current owner.
- Current tests use the current contract.
- Deleting obsolete code does not remove coverage of the active Scribe/extraction path.

## TEST-OPEN-H1: Governance terminal state is ordering-independent

Capture Bundle, Action, and Conclusion by correlation ID. Deterministically exercise:

1. Verdict before Perception.
2. Verdict before Advisory.
3. Perception concurrent with terminal Verdict.
4. Advisory concurrent with terminal Verdict.
5. Late Perception after Conclusion.
6. Late Advisory after Conclusion.
7. Late input beyond the concluded-ID retention boundary.

**Invariant:** One non-reflex correlation produces no more than one final Action and one Conclusion, and terminal late input cannot recreate a second Intent/Security cycle.

**Disposition:** Close OPEN-H1 if all cases pass and all state-creating/publishing paths are guarded. Restore High severity if a duplicate Bundle or downstream cycle is observed.

## TEST-M16: Characterize a stalled subscriber

Stall one subscriber and publish controlled traffic. Confirm publication remains non-blocking and record queue depth, in-flight count, and memory behavior if metrics exist. If capacity policies are later introduced, test the declared policy per subscriber class and prohibit silent loss of persistence/cognitive events.

## TEST-M17: Restart behavior

Required only if agent restart, dynamic lifetime, or shared-bus reuse is supported. Start, stop, and restart an agent on one bus, publish one event, and assert one handler invocation with balanced activity accounting.

## Cross-layer contract tests

### FLOW-1. One submitted turn produces one coherent UI and archive turn

Submit through the supported boundary, capture SSE until terminal conclusion, verify correlation lineage, one projected input, at most one terminal output, and correct durable utterance/reply pairing.

### FLOW-2. Retrieval failure differs from successful empty retrieval

Test successful empty lookup and failed lookup. Intent and UI must preserve absence/unavailability versus present-empty semantics.

### FLOW-3. SSE duplicate and reconnect behavior

Replay events and reconnect during a turn. React must not duplicate rows for one event/correlation, and terminal state must remain stable. If server replay is unsupported, document and test degraded reconnect behavior.

### FLOW-4. Host shutdown leaves recoverable durable state

Block a substrate or persistence operation, request shutdown, verify expected cancellation does not become an unhandled service failure, confirm committed files remain parseable, and verify deterministic recovery after restart.

# Finding disposition checklist

Remove a review entry only when one disposition is recorded:

- **Fixed:** patch reference plus a regression test that failed before and passes after.
- **Disproved:** source-level invariant plus a focused test demonstrating the path cannot occur.
- **Accepted risk:** explicit owner, rationale, supported operational boundary, and monitoring where appropriate.
- **Deferred:** moved to the roadmap with evidence and test design preserved.
